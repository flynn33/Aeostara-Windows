## Confirmed rules that do not need reinvention

ASH's fixed nine-coordinate state model and sixteen-codeword set, canonical classifier and seven class-to-recovery mappings are concrete. Classifier context includes containment, safe halt, admissibility, known correction and fallback availability. The exact mapping is STABLE→NO_ACTION, UNSTABLE→NORMALIZE_STATE, CORRECTABLE→APPLY_CORRECTION, DEGRADED→FALLBACK_REQUIRED, CONTAINED→CONTAINMENT_REQUIRED, FAILED→ESCALATION_REQUIRED, SAFE_HALT→TERMINAL_NO_RECOVERY. Sources: `specs/core/ash-state-space.pseudo.md`, `codeword-set.pseudo.md`, `system-state-classification.pseudo.md::classify_system_state`, `recoverability-semantics.pseudo.md::classify_recoverability` at the ASH pin.

The canonical fallback registry selects by rank, then policy ID, validates candidates and escalates when none is usable. This precedence is source-supported by base `specs/architecture/product_boundaries.md` rule 4 and `ash_authority_and_aeostara_conformance.md`; the general base equal-cost rule cannot replace it. No owner decision is needed to repeat this existing precedence. Concrete domain registry entries, predicates and configuration materialization remain separate inputs.

These rules can be tested with explicit state/class/context inputs. They do not establish how arbitrary JSON becomes a state, whether a desired document is valid, or which JSON writes are authorized by recovery.

## Gaps and their concrete effect

| Gap | Observed source evidence | Consequence and required resolution |
|---|---|---|
| GAP-001: undefined domain projection | Base `specs/algorithms/semantic_projection.pseudo.md::run_semantic_projection` calls `evaluate_domain_rule_for_this_algorithm(normalized)`; `SemanticDimensionBinding.schema.json` only types mappingRule as a string. Other mapping algorithms repeat the undefined helper. | Ordering, failure handling and schemas do not define a concrete evaluator. Propose an explicit profile/rule vocabulary and per-coordinate evidence boundary; distinguish new domain rules from sourced canonical coordinate meaning. |
| GAP-002: projection fixtures lack distinguishing inputs | `fixtures/conformance/semantic_projection_vectors.json` contains `projection-ambiguous-coordinate` and `projection-blocked-mapping` with identical `{"observed":{},"desired":{}}`. Expectations differ: DEGRADED/FALLBACK_REQUIRED versus FAILED/ESCALATION_REQUIRED. No projection spec or distinguishing evidence/context is supplied. | A deterministic native evaluator cannot infer two outcomes from these declared inputs. Proposed supplements must supply actual different semantic inputs and asserted lifecycle phases, or explicitly identify expectations requiring an erratum. Fixture IDs/categories/expected outputs must not determine runtime answers. |
| GAP-003: validator is not an independent semantic oracle | `ci/fixture_validator.py::FixtureSuiteEvaluator._compute_actual` initializes diagnosticKind, stateClass and recoveryCategory from expected; `_compute_projection` only echoes coordinate names/count. `_execute_negative_assertions` recognizes several labels without executing a native engine. | Keep valid schema, Pointer, canonical-hash and structural checks. A green reference run does not prove projection/classification/recovery correctness. Proposed tests must calculate actual outputs from complete inputs in a separate evaluator that cannot read expected answers. |
| GAP-004: recognized-valid authority and recovery inputs | ASH `state-admissibility.pseudo.md::classify_state_admissibility` references recognized/known-valid states but does not enumerate a domain K or bind its selection. Existing base admissibility/recovery vectors have identical empty documents with different expected paths. | Bind immutable domain authority, K/predicate, correction availability, fallback registry, lifecycle context and materialization. Synthetic proposed values may demonstrate the contract but do not become existing ASH authority. Canonical C is fixed and cannot be replaced with K. |
| GAP-005: unsuccessful MappingResult lacks truthful absent-state form | `MappingResult.schema.json` requires projectedState and nine bindings for MAPPED/AMBIGUOUS/BLOCKED/FAILED. `ISemanticProjector.pseudo.md` requires schema-valid blocked results, forbids fabricated state and permits explicit native error results. | A missing projection cannot be filled with zero/default bits or null/omitted required fields. | GAP-006: unavailable facts in other negative results | BackupResult requires backupRecord; ExecutionStepResult requires observedHashAfterStep; RollbackResult requires backupRecordID/restoredHash; FallbackDecision requires selectedCandidateID; VerificationResult requires actualSemanticState, including negative statuses. | Some negative operations genuinely retain these facts; others do not. | GAP-008: immediate class versus later fixture outcome | ASH immediate UNCLASSIFIED defaults to DEGRADED; base `admissibility-unclassified` expects FAILED without distinguishing lifecycle context. Other fixtures assert terminal/recovery paths with absent preceding state/plan/evidence. | Preserve canonical immediate classification. Supplements must explain any later escalation through explicit context/phase; otherwise the expectation remains unresolved. A category label is not a preceding lifecycle execution. |

## Executed source characterization and native limits

`semantic-independent-probes.py` executed successfully and demonstrated identical input objects, expected-seeded actual class/category and schema rejection of absent/null projected state or empty bindings. `semantic-decision-proposal-probes.py` executed successfully and compared distinct numeric spellings/hashes and actual fixture input groups. Their `.json` and logs are external beside the scripts. These are source-characterization checks, not native projection conformance.

The complete base-schema/interface reads, added bindings/architecture/algorithm/fixture reads and exact hashes are recorded in `SOURCE_READING_INVENTORY.json`, `SOURCE_GAP_FOLLOWUP.md`, `PRIMARY_SOURCE_READING_SUPPLEMENT.json` and the independent review JSON. Coverage is scoped and provenance remains role-specific; no claim is made that all repositories or historical files were read.

The unchanged Windows baseline built and passed 129 native cases in each of Debug and Release. An external native reproducer observed six safety failures involving invalid policy, backup copy, restore reporting, partial mutation exceptions and no-drift invariants. These facts are in the baseline logs/provenance/results. They do not certify a new SDK, mapping contract or release.

Independent already-defined-rule work also passed two external native C++20 checks. `semantic-mapping/seven-class-tests` checked the seven canonical class mappings through 112 explicit evaluations. `semantic-mapping/canonical-codeword-tests` compared the fixed enumeration against independent generator closure, checked all 256 XOR pairs and 8,192 transformations, and established the 32 disjoint sixteen-state orbits over all 512 states. Each executable ran as one successful Release CTest test with MSVC 19.44/v143/x64 and Windows SDK 10.0.26100.0. The first used VS 2022 BuildTools; the second explicitly used Community. Adjacent execution JSON and logs bind actual commands, sources, hashes and scope. Neither links AeostaraCore or tests domain K, JSON projection, configuration recovery or an SDK consumer. `PRIMARY_SEMANTIC_SOURCE_READING_SUPPLEMENT.json` records the five ASH files read in full by the primary invocation during this preparation.

## Resolution artifacts and adoption boundary

The shared `JSON_TO_ASH_MAPPING_CONTRACT.md/.json` must separate derived rules, proposed domain rules and unresolved authority; account for all semantic inputs; define all nine coordinates without invented business meanings; preserve the classifier/recoverability context; and specify separately authorized materialization and failure representation. `WINDOWS_SEMANTIC_MAPPING_BINDING.md` maps those meanings to native mechanics. Proposed fixtures and traceability bind source, rule, setup and expected phase without altering upstream files.

The separate review assesses source fidelity, determinism, schema compatibility, fixture consistency and recovery safety. A review-ready proposal remains a proposal. Production adoption requires an authoritative clarification, erratum or supplemental contract with an immutable reference. The owner has authorized preparation and independent already-defined-rule work, not adoption of speculative meanings, frozen public API closure or SDK qualification. No ASH/base edits or pin advancement are authorized.
